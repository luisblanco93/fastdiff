# Architecture

`fastdiff-core` owns repository discovery, NUL-delimited status parsing, staged/unstaged comparisons, bounded patch loading, and aligned rows. `fastdiff-cli` owns the public launcher, helper wire protocol, local single-instance transport, WSL routing, and helper process. `fastdiff-gui` owns rendering, repository tabs, background work, refresh, highlighting, and navigation.

The GUI follows the native setup from the [official eframe template](https://github.com/emilk/eframe_template). egui and eframe are pinned to matching 0.33.3 versions; Cargo.lock pins the resolved dependency graph. Visible rows are virtualized using the [egui scrolling API](https://docs.rs/egui/0.33.3/egui/containers/scroll_area/struct.ScrollArea.html).

Git runs with explicit argument arrays, disabled pagers, colors, external diff drivers, text conversion, and executable clean/process filters. Repositories that transform content through Git filters therefore show raw working-tree content against stored blobs. Status metadata determines file identity; patch headers do not determine filenames. See [Git status](https://git-scm.com/docs/git-status) and [Git diff](https://git-scm.com/docs/git-diff).

## Local launching

The launcher forwards a repository request to the current GUI using a Unix socket on Linux or named pipe on Windows. If no GUI accepts the request, it starts one. A repository request is validated with Git first, then acknowledged before the launcher returns; acknowledgement does not wait for the requested diff to load. Foreground activation is subject to the desktop's restrictions. There is no persistent service or TCP listener. The endpoint and its instance lock live in a per-user runtime directory: `$XDG_RUNTIME_DIR/fastdiff-<uid>` on Linux, or `run` under `%LOCALAPPDATA%\fastdiff` on Windows so the lock never sits in the installer's data root. `FASTDIFF_RUNTIME_DIR` selects another directory.

In WSL, the Linux launcher locates the configured Windows executable, then PATH. The request includes the distribution, Linux user, canonical repository path, and absolute helper path. The Windows GUI executes `wsl.exe` with arguments that start the helper in that distribution as that user. Linux paths remain opaque to Windows; the GUI never opens WSL repository files directly. This follows [Microsoft's interoperability model](https://learn.microsoft.com/en-us/windows/wsl/filesystems).

## Helper boundary

Current 0.1.11 launcher, GUI, and WSL helper builds use protocol 5 and must be updated together from the same release/revision. Retained 0.1.7 artifacts use protocol 4 and work only as a matching set. Verify each launcher with `--version`; never bypass a helper mismatch. Historical release checks are recorded in [validation](validation.md).

The helper exchanges versioned, length-prefixed JSON over stdin/stdout. Frames have bounded size, request IDs, cancellation, and structured errors. An incompatible protocol version produces an actionable failure. Stdout belongs to the protocol; diagnostics go to stderr.

Timeouts, failed writes, reader disconnects or malformed responses, incompatible versions, and unexpected successful response types close and reap the helper. Ordinary operation errors and completed cancellation leave the connection usable. Connection state identifies a failed backend; error text does not control recovery. While disconnected, the worker pauses automatic backend polling and preserves the failure until an explicit refresh.

F5, another `dff` request for the same tab, or tab activation triggers one reconnect attempt on the existing worker thread. Refresh and document commands rediscover the original repository/WSL target and perform the protocol handshake with their cancellation token; only successful discovery replaces the backend. Failure waits for another refresh. Reconnection clears worker-owned status, document, and prepared cache state and reloads an open reflog from page zero. The tab retains its latest view, selected file, document mode, and presentation state through the existing generation handling. Requests arriving during helper cleanup remain queued; a newer request cancels obsolete reconnect work. Initial discovery failures retain the finished-worker restart path.

Repository and diff work runs away from the UI thread. Native filesystem callbacks collect bounded, deduplicated paths; after the 250 ms debounce, the worker filters batches through Git's ignore rules. Tracked files, explicitly opened documents, metadata, ambiguous events and failures remain relevant. Recursive repository coverage includes Git-resolved external metadata and document parents/ancestors. Watcher diagnostics go to stderr without clearing the displayed diff. Native and WSL workers retain two-second freshness checks and manual F5 refresh; inactive tabs pause automatic work. Request generations invalidate stale results. Shutdown closes the protocol, cancels owned Git subprocesses, and reaps helpers; stdin EOF also ends the helper.

Closing a tab cancels its worker and removes the tab without waiting for teardown. The app retains the worker's join handle and collects it after the worker finishes its existing backend/helper cleanup. Full application exit cancels every remaining worker before waiting for all live and retired workers; uncooperative cleanup can still delay exit. Cleanup checks request a repaint after 50 ms only while retired workers remain.

## Scope

All combines the current Git index and working tree with committed local changes. Unpushed discovery resolves upstream and HEAD once per refresh and pins their merge base and HEAD IDs in comparison metadata; patches use those IDs even if refs move later. Rename paths remain independent of working-tree rename metadata. Missing upstream/history is a notice, while other Git failures remain errors. An unborn repository still shows working additions.

Protocol 5 carries explicit repository/document targets, compact document text, and reflog page/snapshot requests. The GUI worker prepares document rows locally. Document targets bypass mandatory Git discovery; WSL document reads stay in the Linux helper. Parent-directory watches and periodic refresh reread paths after atomic replacement. Install matching launcher, GUI, and helper builds together. The app reads files and repository state and allows copying; it never edits, stages, resets, or creates checkpoints.

The core exports `ReflogEntry`, `ReflogRequest`, and `ReflogList`; repository, backend, and helper methods expose current branch and HEAD reflog metadata. Reflog is separate GUI/worker state from the file-comparison `View`. Its polling path bypasses status, document reads, and diffs. Mode changes cancel active work, clear pending searches, and reject stale generations; restarting the worker restores the active mode. The GUI virtualizes informative reflog rows without diff navigation. See [usage](usage.md) for navigation and theme behavior.

Reflog discovery starts with 15 entries and automatically loads another 15 when the final three loaded rows become visible. Page zero reads 16 entries for lookahead; continuation reads overlap the previous boundary and preserve scroll on append. A Git-resolved metadata fingerprint avoids another reflog query on unchanged periodic checks. Snapshot or boundary changes reload the newest page and reset scroll; a racing query retries once before reporting a reflog-only error. Unreliable fingerprint layouts replace the loaded prefix under the existing output cap, retaining older-history access at the cost of repeated prefix reads. Each tab allows one continuation at a time; page errors retain rows with a retry action, and F5/reopening/activation reload page zero. Queries remain cancellable and bounded to 16 MiB. NUL-delimited fields carry the full ID, short ID, current ref decorations, reflog selector, and action. Entries stay in Git’s newest-first order, including repeated commit IDs and detached checkouts, without upstream filtering or fetching.
